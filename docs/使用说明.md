## 1. 简介与架构

tk-report 是一个**独立的报表组件仓库**（pnpm + Maven monorepo），前端设计器走 D 盘 `@niqer/report` Web Component，后端是 Spring Boot Starter + PDF 边车。

核心设计理念：**一份布局引擎源码（`report-core`），前端预览与后端渲染共用**，保证「设计器所见 = 最终 PDF / Excel」的**零漂移**。

板块：

| 包 | 路径 | 技术栈 | 职责 |
|----|------|--------|------|
| `@niqer/report-core` | `packages/report-core` | 纯 JS | 布局引擎内核（展开 / 分页 / 合并 / 表达式），框架无关 |
| `report-tool-web` | `apps/report-tool-web` | 原生 WC | 外壳：登录 / 路由 / 账号，引用报表工具并注入存储与数据源插件 |
| `@niqer/report` | `D:/niqer-report` | 原生 WC | 报表工具：设计器 + 预览；内部使用 `@niqer/pdf`、`@niqer/barcode` |
| `report-spring-boot-starter` | `report-starter` | Java 17 + Spring Boot | 后端：模板存储、数据填充、鉴权、打印计数、调用边车 |
| `report-pdf` 边车 | `report-pdf` | Node | 独立渲染服务：模板 JSON → PDF / XLSX / HTML |

**端到端数据流：**

```
设计器画模板 ──保存 JSON──▶ 后端（对象存储）
                                │
运行时：宿主传 templateId + 业务参数
     └─▶ ReportPreviewService 跑 dataset 里的 SQL / API 填充真实数据
            └─▶ ReportRenderService 把「已填模板」发给边车
                   └─▶ report-pdf 布局(core) + 绘制 ──▶ PDF / XLSX / HTML 字节
```

前端预览走同源路径：浏览器内用 `report-core` 展开 + DOM 度量 + 渲染，与边车产物完全一致。

## 3. 环境准备与本地开发

### 依赖

- Node ≥ 18，pnpm `11.15.1`
- JDK 17，Maven
- （可选）Docker，用于边车镜像
- 对象存储（默认 MinIO）+ 数据库（PostgreSQL，SQL 校验按 PG 语法）

### 安装与构建

```bash
# 仓库根目录
pnpm install                                   # 安装前端依赖
mvn -f report-starter/pom.xml -DskipTests install   # 构建并安装 starter 到本地仓库
```

### 本地启动边车

```bash
pnpm engine:serve
# 或
cd report-pdf && npm run engine:serve
```

> 边车默认监听 `http://127.0.0.1:7321`。生产构建前需将字体文件放入 `report-pdf/fonts/`（度量与绘制必须同一批字体文件）。

## 4. 快速开始（三步接入）

### 第一步：启动边车

```bash
docker compose -f docker-compose.report.yml up -d
# 健康检查
curl http://127.0.0.1:7321/health
```

### 第二步：后端接入（Spring Boot）

1. 引入依赖：

```xml
<dependency>
  <groupId>com.niqer.report</groupId>
  <artifactId>report-spring-boot-starter</artifactId>
  <version>1.0.0</version>
</dependency>
```

2. 配置 `application.yml`：

```yaml
report:
  enabled: true                 # 缺省即为 true
  pdf:
    sidecar-url: http://127.0.0.1:7321/render
  storage:                      # 默认 MinIO；也可自己提供 ReportObjectStorage bean
    endpoint: http://127.0.0.1:9000
    access-key: xxx
    secret-key: xxx
    bucket: report
  auth:
    enforce-admin: true         # 开发期可设 false 放开管理接口
  license:                      # 收费版：部署时写入，界面不提供激活
    key: NQL1....               # 或环境变量 REPORT_LICENSE_KEY
    # file: /etc/report/license.key
```

3. 提供必需的 Bean（详见 [SPI 扩展点](#11-spi-扩展点)）：
   - `DataSource` / `JdbcTemplate`（默认 `JdbcReportSqlExecutor` 依赖它）
   - `ReportAuthGuard`（`enforce-admin: true` 时必须提供，否则管理接口全部 403）

4. 执行建表 DDL（宿主若无该表）：`report-starter/src/main/resources/db/report_template_binding.sql`

### 第三步：前端接入（独立工具）

外壳只引用报表工具。PDF / 条码是设计器与预览的内部能力，不要在外壳再引一遍。

```json
"@niqer/report": "file:D:/niqer-report"
```

```js
import '@niqer/report'

const tool = document.createElement('niqer-print-tool')
tool.apiBase = '/report'
tool.templateApi = '/report/mode'
tool.getAuthHeaders = () => ({ Authorization: 'Bearer ' + token })
tool.storagePlugin = storagePlugin
tool.datasourcePlugin = datasourcePlugin
document.body.appendChild(tool)
```

独立工具外壳把 `/report/tool/storage`、`/report/tool/connections` 包成插件再注入。未注入则不显示存储入口和连接管理，也不请求 `/report/tool/*`。

`<niqer-print-tool>` 常用属性：

| 属性 | 默认 | 说明 |
|------|------|------|
| `api-base` | `/report` | 后端接口基础路径 |
| `template-api` | `/report/mode` | 模板读写接口 |
| `getAuthHeaders` | `() => ({})` | 请求附加头 |
| `storagePlugin` | 无 | 有则模板页签出现存储入口（`get` / `save` / `test`） |
| `datasourcePlugin` | 无 | 有则右栏出现「连接管理」页签，SQL 下拉走 `list` |

## 5. 报表设计器使用指南

打开独立工具页面即进入三栏工作区。

### 界面布局

- **顶部工具栏**：纸张尺寸、对齐/分布、文本样式（加粗/对齐/垂直对齐）、边框、单元格合并、预览与打印入口。
- **左栏**（三个页签）：
  - **模板**：加载、导入、导出、保存模板；注入存储插件后可配置本地目录 / MinIO。
  - **组件**：拖拽 4 种组件到画布 —— 文本、图片、二维码、条形码。
  - **属性**：选中元素后编辑位置、尺寸、字体、对齐、边框、数据绑定、条件底色、合并方式等。
- **中间画布（DesignArea）**：纸张画布，含 4 条可拖拽的**分区边界线**（见下）。
- **右栏**页签：
  - **参数**：定义业务查询参数。
  - **数据集**：定义 `ds1`/`ds2`… 数据集（SQL / API）。
  - **连接管理**：注入数据源插件后出现，列出全部 JDBC 连接，可新增 / 编辑 / 测试 / 设默认 / 删除。

### 分区边界线（关键概念）

画布上 4 条线把页面划成 5 个区，决定元素的分页与重复行为：

| 边界线 | 上方区域 | 行为 |
|--------|----------|------|
| 页眉线 `headerY` | 页眉区 | 每页顶部重复 |
| 汇总 A 线 | 数据区（明细） | 重复行模板按数据逐条展开、流式分页 |
| 汇总 B 线 | 汇总区 | 每页一次，紧跟本页最后一条数据（可放小计 `subtotal`） |
| 页脚线 `footerY` | 汇总 B→页脚区 | 仅末页显示一次（放全局合计 `sum`、签章、备注）；文本按内容自增高，放不下则另起一页 |
| （页脚线下方） | 页脚区 | 每页底部重复、钉页底 |

### 数据集（SQL / API）

在右栏「数据集」中新增 `dsN`：

- **SQL 类型**：填写 `select ...` 语句，用 `#{参数名}` 占位业务参数。后端执行时会自动加只读/超时/行数上限保护（见 [API](#8-http-api-参考) 与 [配置](#9-后端配置参考)）。
- **API 类型**：填写 URL，用 `#{参数名}` 占位；后端代拉取并把 JSON 填入该数据集。URL 需在白名单内（`report.api.allowed-url-prefixes`），或以 `/api` 开头走内部转发。

> SQL 会被强制校验：必须以 `select`/`with` 开头、单条语句、禁止 `insert/update/delete/drop/...` 等危险关键字。

### 预览与导出

- **前端预览**：用 `report-core` 在浏览器内展开+度量+渲染，速度快、所见即所得。
- **PDF / HTML 预览**：调用后端 `/report/pdf/preview`、`/report/html/preview`（取样数据，行数受 `report.sql.preview-timeout-ms` 与预览行上限约束）。
- **正式打印 / 下载**：走 `/report/pdf`（全量）、`/report/xlsx`（可编辑且版式还原的 Excel）。

### 模板管理与菜单绑定

- 模板以 `.nqt` 二进制封袋存于对象存储（混淆 + 加密）。设计器读写 `/report/mode/{fileName}` 时仍使用解密后的 JSON。批量导出为单个 `.nqt` 或多个 zip。
- 通过 `/report/binding` 把「菜单」与「模板编码」绑定，业务页面即可按菜单名列出可用报表。

## 6. 模板表达式语法

模板元素的文本内容里使用 `${...}` 占位符，由 `report-core` 统一解析（前端预览与边车渲染同一份语义）：

| 语法 | 含义 | 示例 |
|------|------|------|
| `${dsN.字段}` | 数据集字段引用；位于数据区时按行迭代 | `${ds1.goodsName}` |
| `${param.字段}` / `${字段}` | 业务参数引用 | `${param.orderNo}` |
| `${sum(dsN.字段)}` | 全局合计（放汇总 B→页脚区） | `${sum(ds1.amount)}` |
| `${subtotal(dsN.字段)}` | 本页小计（放汇总区） | `${subtotal(ds1.amount)}` |
| `${page}` | 当前页码 | `第 ${page} 页` |
| `${total}` | 总页数 | `共 ${total} 页` |
| `${row(dsN)}` | 行序号 | `${row(ds1)}` |
| `${count(dsN)}` | 数据集行数 | `${count(ds1)}` |
| `${now('yyyy-MM-dd HH:mm:ss')}` | 当前时间（可带日期格式） | `${now('yyyy-MM-dd')}` |
| `${timestamp(dsN.字段)}` | Unix 网络时间戳（UTC 秒） | `${timestamp(ds1.print_at)}:${ds1.print_status_code}` |

数据集接口约定：`dsN` 若返回 `{ data: [...] }` 结构会自动取 `data` 数组进行迭代。

聚合括号内支持常数与 `dsN.字段` 的简单算术（如 `${sum(ds1.qty * ds1.price)}`），基于 `decimal.js` 高精度计算，不使用 `eval`。

## 8. HTTP API 参考

### 后端 `/report`（模板与渲染）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/report/mode?pageNum&pageSize` | | 分页列出模板编码 |
| GET | `/report/mode/{fileName}` | | 读取模板内容 |
| PUT | `/report/mode/{fileName}` | 管理员 | 新增/更新模板（body `{content}`） |
| DELETE | `/report/mode` | 管理员 | 批量删除（body 为编码数组） |
| PATCH | `/report/mode/rename` | 管理员 | 重命名（`{oldFileName,newFileName}`） |
| POST | `/report/mode/export/batch` | 管理员 | 导出（单个 `.nqt` / 多个 zip） |
| POST | `/report/sql/parse` | | 解析 SQL，返回列名集合 |
| POST | `/report/sql/preview` | | 构建取样预览模板（含填充数据） |
| GET | `/report/sql/schema` | 管理员 | 列出库表结构（`information_schema`） |
| POST | `/report/pdf` | | 渲染 PDF（全量，`inline`） |
| POST | `/report/pdf/preview` | | 渲染取样 PDF |
| POST | `/report/html/preview` | | 渲染取样 HTML |
| POST | `/report/xlsx` | | 导出 XLSX（全量，`attachment`；免费版 403） |
| GET | `/report/license` | 管理员 | 只读授权状态（`edition` / `active` / `sub` / `exp`），不提交授权码 |

渲染类接口的 body 通常为：`{ "templateId": "...", "参数名": "值", ... }`。

### 后端 `/report/binding`（菜单绑定）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/report/binding?menuName=` | | 按菜单名列出模板 |
| GET | `/report/binding/all` | 管理员 | 列出全部绑定 |
| POST | `/report/binding` | 管理员 | 新增/更新绑定 |
| DELETE | `/report/binding` | 管理员 | 删除绑定（body 为 id 数组） |

### 边车（Node 渲染服务）

| 方法 | 路径 | 返回 | 说明 |
|------|------|------|------|
| GET | `/health` | JSON | 健康检查 + 字体注册状态 + 池/缓存指标 |
| POST | `/render`（或 `/render/pdf`） | `application/pdf` | body = 已填 dataset 的模板 JSON |
| POST | `/render/xlsx` | xlsx | 同上 |
| POST | `/render/html` | `text/html` | 预排 HTML（预览专用） |

响应头包含 `x-report-pages`、`x-report-elements`、`x-report-ms`、`x-report-cache`。

## 9. 后端配置参考

前缀 `report.*`（`ReportProperties`）：

### `report.storage`（对象存储）

| 键 | 默认 | 说明 |
|----|------|------|
| `type` | `minio` | 存储类型 |
| `endpoint` | — | MinIO 地址（用默认实现时必填） |
| `access-key` / `secret-key` | — | 凭证 |
| `bucket` | `report` | 桶名 |
| `secure` | `false` | 是否 HTTPS |
| `prefix` | `reports/` | 对象前缀 |

### `report.pdf`（边车/渲染）

| 键 | 默认 | 说明 |
|----|------|------|
| `sidecar-url` | `http://127.0.0.1:7321/render` | PDF 渲染地址 |
| `sidecar-xlsx-url` / `sidecar-html-url` | 空（由 sidecar-url 推导 `/xlsx`、`/html`） | 覆盖地址 |
| `timeout-ms` | `60000` | 请求超时 |
| `connect-timeout-ms` | `3000` | 连接超时 |
| `retries` | `2` | 重试次数 |
| `gzip` | `true` | 请求体压缩 |
| `gzip-min-bytes` | `8192` | 压缩阈值 |
| `max-rows` | `100000` | 全量渲染行数上限 |
| `sql-timeout-ms` | `30000` | 全量 SQL 超时 |

### 其它

| 键 | 默认 | 说明 |
|----|------|------|
| `report.sql.preview-timeout-ms` | `5000` | 预览 SQL 超时 |
| `report.api.through-gateway` | `false` | `/api` 内部转发是否经网关 |
| `report.api.allowed-url-prefixes` | 空 | API 数据集 URL 白名单（逗号/换行分隔） |
| `report.auth.enforce-admin` | `true` | 是否强制管理员校验 |
| `report.enabled` | `true` | 关闭则不装配 |

### `report.license`（收费版授权，部署配置，无界面激活）

独立工具与嵌入宿主共用同一套配置。无有效授权即为免费版（预览/打印带水印，无 Excel）。

| 键 | 默认 | 说明 |
|----|------|------|
| `key` | 空 | 授权码正文 `NQL1....`；也可用环境变量 `REPORT_LICENSE_KEY` |
| `file` | 空 | 授权码文件路径（整文件即一行授权码）；也可用 `REPORT_LICENSE_FILE`。文件存在且验签通过时优先于 `key` |

**独立工具**：未配 `file` 时自动读 `{report.tool.data-dir}/license.key`（默认 `./data/license.key`）。也可直接写进 `apps/report-tool-api` 的 `application.yml`。

**嵌入宿主**（如 tk-erp）：在宿主 `application.yml` 写 `report.license.key`（或挂载文件并写 `report.license.file`）。Starter 不会默认某个数据目录文件。

改授权后重启进程生效，没有运行时写入接口。

## 11. SPI 扩展点

Starter 在宿主未提供对应 Bean 时给出默认实现（`@ConditionalOnMissingBean`）。宿主可自定义覆盖：

| 接口 | 默认实现 | 是否需宿主提供 |
|------|----------|----------------|
| `ReportSqlExecutor` | `JdbcReportSqlExecutor`（依赖 `JdbcTemplate`） | 需有 `DataSource`；执行报表 SQL/绑定查询 |
| `ReportObjectStorage` | `MinioReportObjectStorage`（需 `report.storage.endpoint`） | 可换成自有存储 |
| `ReportAuthGuard` | 默认：`enforce-admin=true` 时抛 403 | **强烈建议提供**，实现 `requireAdmin()` |
| `ReportPageKeyResolver` | 默认恒等（`menuName → menuName`） | 菜单名→pageKey 映射不同时提供 |
| `ReportPrintCallback` | 空实现 | 可选；模板填数后、渲染前回调宿主（宿主可在此做打印计数等业务，**报表不内置 print_count**） |

`ReportAuthGuard` 还可覆盖 `forwardAuthHeaders(...)`，在 API 数据集回源时透传鉴权/语言头。

设计器「打印次数」页签已下线。

示例：

```java
@Bean
public ReportAuthGuard reportAuthGuard() {
    return () -> {
        if (!currentUserIsAdmin()) {
            throw ReportException.forbidden("需要管理员权限");
        }
    };
}
```

## 12. 部署

### 构建边车镜像

```bash
# 构建前把 Windows/Linux 字体放入 report-pdf/fonts/
docker build -f report-pdf/Dockerfile -t report-pdf:1.0.0 .
docker compose -f docker-compose.report.yml up -d
```

宿主 Spring 配置指向边车：

```yaml
report:
  pdf:
    sidecar-url: http://report-pdf:7321/render
  license:
    key: NQL1....
```

独立工具部署也可把授权码放进数据目录 `license.key`，或设置 `REPORT_LICENSE_KEY` / `REPORT_LICENSE_FILE`。

### 被 tk-erp 引用

推荐与 `tk-erp` 并列克隆（`D:/tk-erp`、`D:/tk-report`）。前端开发期用路径依赖：

```json
"@niqer/report-core": "file:../tk-report/packages/report-core",
"@niqer/report": "file:D:/niqer-report"
```

后端无私服时先 `mvn -f report-starter/pom.xml install`，宿主再声明依赖。

## 13. 常见问题与排错

| 现象 | 可能原因 / 处理 |
|------|------------------|
| 管理接口全部 403 | `report.auth.enforce-admin=true` 但未提供 `ReportAuthGuard` bean；开发期可设为 `false` |
| `report.storage.endpoint is required` | 用默认 MinIO 存储但未配置 endpoint，或自行提供 `ReportObjectStorage` |
| SQL 报「forbidden keyword / must start with select」 | 数据集 SQL 必须是单条只读 `select`/`with` 语句 |
| API 数据集报「host not allowed」 | 目标 URL 不在 `report.api.allowed-url-prefixes` 白名单内 |
| 预览与 PDF 版式不一致 | 确认边车字体与度量字体一致；生产用 `REPORT_FONT_*` 指向同源字体文件 |
| 预览窗口打不开 | 浏览器拦截弹窗；`openSqlReportPreview` 需允许弹窗 |
| 大报表渲染超时 | 调大 `report.pdf.timeout-ms` 与边车 `REPORT_JOB_TIMEOUT_MS`；必要时增 `REPORT_WORKERS` |
| 数据集报 missing params | SQL/API 里的 `#{参数}` 未在业务参数中提供 |
